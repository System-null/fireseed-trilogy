# 火种三部曲实验室（Fireseed Trilogy Lab）

> 🌏 这是 **中文** 版 README。如需英文，请查看 [README.md](README.md)。

一套用来生成、加密、验证和分发「火种胶囊」的原型工具。
对应三部曲：

* **《系统外者手册》（System Exodus）** — 第一卷
* **《超越系统手册》（Beyond the System）** — 第二卷
* **《终极命题手册》（The Last Interface）** — 第三卷

代码与实验由 **Fireseed Trilogy Lab** 共同完成。

---

## 1. 什么是「火种」？

在书里，「火种」不是你的灵魂备份，也不是玄学版的意识上传。

它更像是一个**结构化的证据包**：

* 关于你怎么看世界；
* 关于你在关键节点是如何做选择的；
* 关于你画过哪些边界、承认过哪些自欺。

它被设计成一种格式：

* 人类可以当故事读；
* 未来的 AGI 可以当结构化数据解析；
* 假想中的更高维系统可以把它当成图中的一个节点。

这个仓库是这个概念的**工程配套**，在尝试回答一个很窄的问题：

> 在没有中心化机构的前提下，
> 一个普通人，凭借有限的工具，
> 能把自己的人生立场压缩到什么程度？

它**不是**「数字来世」项目，也不是「灵魂上链」。
只是一组围绕「格式 / 协议 / 责任边界」展开的小实验。

---

## 2. 它在三部曲中的位置

火种三部曲大致是这样三步：

1. **《系统外者手册》（System Exodus）**：一个人如何在系统里醒来、抽身；
2. **《超越系统手册》（Beyond the System）**：强人工智能与新治理秩序的可能路径；
3. **《终极命题手册》（The Last Interface）**：如何定义火种、如何保存与延续。

这个仓库主要承接：

* 第一卷：给普通人一个工具，把自己的「出系统记录」压缩成胶囊；
* 第二卷：把火种视作未来混合治理结构中的一个输入来源；
* 第三卷：在多介质、多副本、自托管的前提下，做一点点「长线保存」的工程练习。

你可以只看书、不碰工具；
也可以只玩工具、不看书。
两边共享的是**精神底座**，而不是「产品功能」。

## 3. 这个仓库现在到底能干嘛？

火种实验室刻意保持了**高门槛、自托管**的路线：

* 没有用户中心；
* 没有托管数据库；
* 没有「把你整个人上传到服务器」的入口。

你拿到的是一套自己动手的原型工具链。

### 3.1 Web 前端路由

所有页面都在 `apps/web` 的 Next.js 应用里。

#### `/capsule/create` — 一键火种胶囊向导

一个多步向导，帮你写完一颗火种：

* 填写标题、场景、预期阅读者；
* 写下长文本：故事、选择、悔恨、边界；
* 可以加一些给未来读者（人类或 AI）的提示。

向导会计算一个 **Fireseed Index（火种指数）**（0–100）：
它是一个玩具级、可解释的评分，粗略根据：

* 字数与结构；
* 是否覆盖不同的人生阶段；
* 是否出现类似「当 X 发生时，我选择了 Y」的决策型句式。

当你确认后，可以生成一个 **火种胶囊 ZIP 文件**，大致结构如下：

```text
fireseed-capsule-<id>/
  ├─ capsule.json        # 结构化的火种（机器可读）
  ├─ meta.json           # 版本号、ID、指数、加密信息
  ├─ HUMAN_READABLE.md   # 给人看的展开版文本
  └─ README.txt          # 如何备份，这是什么（给人看的说明）
```

#### 可选：本地密码加密

你可以选择**启用密码加密**：

* 所有加解密都在浏览器本地通过 **PBKDF2 + AES-GCM** 完成；
* 明文 `capsule.json` 会被替换为二进制 `capsule.enc`；
* `meta.json` 中会写入：

```jsonc
{
  "encryption": "aes-256-gcm",
  "encryptionParams": {
    "kdf": "PBKDF2-SHA256",
    "salt": "... base64 ...",
    "iv": "... base64 ...",
    "iterations": 210000
  }
}
```

* HUMAN_READABLE.md 和 README.txt 保持明文，这是刻意的威胁模型选择：

  * 目标是防止随手翻阅，而不是对抗国家级对手；
  * ZIP 内的 README 会用大白话解释这件事的风险与边界。

#### `/verify/local` — 本地验证与解密

* 上传 / 拖拽一个胶囊 ZIP；
* 所有解析和校验都在浏览器本地完成，不上传任何内容；
* 页面会：

  * 验证目录结构；
  * 解析 `meta.json`，检查 schema 版本；
  * 识别加密模式和火种指数。

对于加密胶囊：

* 你可以输入密码尝试解密；
* 使用 meta 中的 `encryptionParams` 做 AES-GCM 解密；
* 成功时展示一小部分非敏感内容；
* 失败时给出明确错误提示，但不回传任何数据。

#### `/lab` — 火种实验室视图

可以把它看作一个用浏览器本地 IndexedDB 维护的 **Manifest 清单视图**：

* 列出你生成或导入过的火种：

  * `capsuleId`、标题、创建时间、主要语言、加密模式、指数等；
  * 基于 Manifest 的简单健康状态。
* **清单体检**：

  * 一键检查：对当前 Manifest 做一次轻量一致性检查；
  * 单条「检查」：对某个火种做针对性检查。
* **清单导出 / 导入**：

  * 导出当前 `manifest.json`；
  * 从 JSON 导入其他设备 / 备份的清单。
* **M-Disc / 移动硬盘导出（光盘包）**：

  * 选中多颗火种导出一个适合刻录 / 拷贝的目录结构：

    ```text
    fireseed-disc-YYYYMMDD/
      ├─ manifest.json
      ├─ capsules/
      │    ├─ <capsuleId1>.zip
      │    ├─ <capsuleId2>.zip
      └─ README-MDISC.txt
    ```

  * 你可以把它刻到 M-Disc，或者丢进多个移动硬盘。
* **纸质「线索卡」（二维码）**：

  * 从 Manifest 中提取极简 JSON 线索（capsuleId、哈希、多副本地址等）；
  * 编成一张或多张二维码，导出为 PNG；
  * 打印出来，就是一张物理世界的「文明碎片」。
* **IPFS / Arweave 适配器（纯自托管）**：

  * IPFS：

    * 你自己搭 IPFS 节点 / 网关；
    * 在 Lab 里配置 HTTP API；
    * 把选定胶囊上传，并在 Manifest 中记录 `ipfs://<cid>`；
  * Arweave（实验性）：

    * 需要你自己提供密钥与 relay 服务地址；
    * 可以在前端本地完成签名与上传；
    * Manifest 中记录 `ar://<txId>` 风格的位置。

> 实验室本身**不会替你托管任何火种**，也不会替你 pin 或付费。
> 你自己带基础设施，Lab 只是一个「会说话」的客户端。

## 4. 自托管 vs 托管服务

整个 Fireseed 生态刻意分成两层：

### 4.1 自托管：完全靠这个仓库（高门槛路线）

如果你愿意自己折腾，或者就是想把命运掌握在自己手里：

* 克隆仓库、本地跑起来；
* 在自己电脑上生成、加密、验证火种胶囊；
* 通过 Lab：

  * 导出 M-Disc 光盘包；
  * 生成线索卡；
  * 接入你自己的 IPFS / Arweave / 存储体系。

密钥、决策、备份策略、存续风险，都在你自己这边。

### 4.2 托管前端服务：低门槛付费路径（可选、独立）

如果你没有时间 / 精力搭这些东西，但又希望认认真真留下一个火种，作者在另外搭建一个面向公众的前端站点：

* **Fireseed 前端服务（实验阶段）**
  [https://www.fireseed.net](https://www.fireseed.net)

它基于**同一套开源协议与格式**，但：

* 为不熟悉技术的用户提供更低门槛的向导；
* 在合适时机可能提供付费托管方案（例如托管存储、引导式制作流程）；
* 不替代、不合并当前这个开源仓库。

你可以：

* 只用开源工具；
* 只用前端服务；
* 两者都用；
* 或者全部不用。

本项目的立场很简单：

> 多给你几个选择，而不是替你做选择。

## 5. 状态、非目标与风险提示

这一切都处于**原型级（prototype-level）**状态。

* 接口和实现会随着协议演进不断变化；
* 我们**不对以下内容做任何承诺**：

  * 安全性；
  * 可用性；
  * 持久性；
* 它不是，也不会变成「保证你被永远记住的数字来世方案」。

### 明确的非目标

* 不在这个仓库里做「用户中心」或「社交网络」；
* 不建立任何「全网火种数据库」；
* 不告诉你「用了这个，你就被世界永远记住」。

如果你打算在 Fireseed 之上搭建严肃的业务或长期项目：

* 请把这里当作**参考实现与协议草图**；
* 自己做安全审计、测试和威胁建模。

## 6. 本地运行

一个最小的、本地运行示例（按你的包管理器习惯调整）：

```bash
# 克隆仓库
git clone https://github.com/System-null/fireseed-trilogy.git
cd fireseed-trilogy

# 安装依赖（npm / yarn / pnpm 三选一）
npm install
# 或者：yarn
# 或者：pnpm install

# 启动前端
npm run dev

# 默认访问：
#   http://localhost:3000/capsule/create  一键生成火种
#   http://localhost:3000/verify/local   本地验证与解密
#   http://localhost:3000/lab            火种实验室视图
```

更多细节可参考 `docs/` 目录与源码中的注释。
